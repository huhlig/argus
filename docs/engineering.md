# Engineering conventions

## Quality commands

```text
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo run -p argus-cli -- --help
```

CI runs the same commands. Unsafe Rust is forbidden workspace-wide.

## Dependency direction

`argus-core` is the dependency root. Snapshot, storage, and language contracts may
depend on core. The CLI may depend on inward-facing libraries. Production crates
must not depend on `argus-test-support`. `scripts/check-dependencies.ps1` enforces
the initial rule without adding a third-party dependency.

## Errors and tracing

Library errors use `argus_core::ArgusError` with a stable `ErrorCode`; context is
human-readable and sources are retained. Libraries do not print. The CLI owns
presentation and exit codes.

Subsystems will emit structured tracing fields (`run_id`, `work_id`, `target_id`,
and `attempt_id` when applicable). A tracing implementation is deferred until a
long-running operation exists.

## Fixtures

Small repositories belong under `fixtures/repos/<scenario>`. Each fixture is
self-contained, documents its intended clean, dirty, generated, malformed, or
multi-crate state, and avoids global Cargo or Git configuration. Dirty-state
manifests and binary inputs are generated by test builders when needed.
